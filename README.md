本次改善短暂握手重置和连续网络通知后的恢复。核验期间暂停转发，仍须取得最新出口证明才能恢复；原核验有效期、固定出口和断网保护保留。已有正常配置无需重复填写。

四段代理资料现在可选择“自动识别 HTTPS／HTTP／SOCKS5”，本人确认后检测并核对固定出口。带协议的链接仍按原协议处理，已保存的正常连接无需重新配置。

“本机状态”新增“测试断网保护”按钮：先保存工作，再暂停专用转发、逐应用确认实际结果并恢复原连接。Wi-Fi、Clash 与系统保护保持。两分钟后自动尝试恢复；无法确认或未测试的项目不会自动显示通过。


“CLI 固定出口”页面新增“打开 Claude Code”和“在项目文件夹打开…”按钮，使用原 CEGR 受保护启动器在终端中启动。原固定出口和保护保持，连接或保护未就绪时不会改用其他入口。


新客户：下载并解压，将助手拖入“应用程序”后打开，再按引导激活、确认连接和所需应用。系统密码只在 macOS 的授权窗口中填写。

已安装客户可在助手的“软件更新”中检查更新。更新前保存正在使用的浏览器、Claude 桌面端与 Claude Code 工作；原固定出口、连接配置和断网保护保留。若系统提示更新保护组件，请按提示完成授权，无需反复填写端口或重建连接。

从 1.0.19 或更早版本升级且曾配置 Edge 的客户：更新后先保存并退出所选应用，在“浏览器固定出口”中准备安装文件，再到系统设备管理确认安装，随后重开 Edge 核验。只更新助手不会自动完成描述文件安装；原代理、固定出口及其他应用设置保留。

日常使用：打开助手查看连接状态，再使用常用应用即可。首页分别提供浏览器、客户端和 CLI 固定出口入口；点击进入各自独立页面，顶部可返回首页，详细诊断按需展开。出现问题可导出日志交给支持人员，日志不会自动上传。

首次使用需要完成激活、确认连接和应用范围。已有 Clash 时可自动发现本地入口，再由本人确认要保留的出口 IP；规则模式下仍需核对目标应用的实际路由。

“英文＋美西时区”和“清理 Claude 站点数据”均需主动操作，安装更新不会自动执行。清理保留书签、密码及下载文件；系统设置与清理前仍会要求相应确认。连接配置通过不等于已完成所有应用及异常恢复测试，也不保证第三方账号状态。

## Chrome 与组织 DNS 策略冲突

若「应用保护检查」明确显示 Chrome 的 `DnsOverHttpsMode` 冲突，且其余 Chrome 设置匹配，可选择「改为沿用已有 Chrome DNS 策略」。先阅读说明并确认，再保存工作、正常退出所选应用，按提示在系统设备管理中安装新的 CEGR 描述文件。

这个选项只移除 CEGR 自身的 Chrome DNS 设置；固定代理、原 IP、断网保护及其他应用设置保持。Chrome DNS 改由已有受管策略管理，**此模式不保证 DNS 加密或隐私**。不要移除公司描述文件，也不要关闭「域名隐私保护」总开关来代替这一选项。

助手会核对系统中真正安装的配置版本。只打开文件、取消安装或仍有 DNS 模板冲突，都不会显示完成；已有冲突时也不会反复要求安装。取消切换不会自动撤销已经安装到系统中的配置，须按检查结果继续处理。可从同一位置恢复 CEGR 加密 DNS；若公司策略仍强制关闭，则会继续提示冲突。


出现问题时请保留错误提示、发生时间及诊断日志。不要为了排障关闭过滤器、换陌生出口、停用公司安全软件或清空全部浏览器数据。
